# 路线与路面

## 硬规则
- **永远往前走**（用户 2026-10-18：“地图还是往前走的”）：朝一个总方向前进的之字形，不盘旋、不回头、不绕圈。
- **路宽、容错高**：OMG 路宽 2.6 / 2.5 / 2.4（线宽 1.0 的 2.4–2.6 倍），之前是 2.2/2.0/1.8（f37b6d1）。路边裁切 6%（6393a5d / 31fd69a）。
- **线头朴素**：无描边、无光晕、无接触圆盘；线头用拖尾的同一材质（同一皮肤颜色/纹理，经典皮肤用关卡色，绝不默认白色），死亡碎片也一样。
- 不能有东西挡住线头和接下来几秒的路（见 nj-camera 的视线规则、nj-scene-design）。

## 前进式路线生成：`tools/research/route_forward.py`
```sh
python3 tools/research/route_forward.py --song omg [--xmax 12] [--dir levels-src]
python3 levels-design/validate.py omg --dir levels-src
```
- 方向只有 N（前进）、E、W（横向）。从 N 点一下转 E（R）或 W（L）；从 E/W 下一下必须转回 N → 沿 N 的进度永不减少。
- 每 2 小节乐句是一段朝一侧的阶梯，乐句之间左右交替（阶梯组成的前进之字形）；快出 ±XMAX 走廊时提前换边；下一段前进条会碰到之前的路时拒绝该侧。
- 结果确定性：同样的音乐得到同样的形状。
- validator 的 FORWARD 硬规则（2961ddc）：沿地图总轴的进度不得减少；每个 16 s 窗口偏离总方向不超过约 34°。

## 几何细节（8d29dd2 方角）
- 线沿中心线走，严格 90° 方角（没有滑行过渡；晚点击先冲过再弹回）。拖尾 = 每段直线一个轴对齐盒子原地增长（腾空后新起一段）。
- 路面转角精确拼接：转角方块归进入段，离开段从转角后半个上一段宽度开始；适用于宽度变化；路块相接不重叠，路体/路顶叠放无共面。
- 判定：窗口 = (路宽/2)/速度，上限 150 ms，不超过相邻点距一半；晚点击只要线头中心还在路上就算；早点击在窗口内吸到转角上。
- `tools/qa/tolerance.ts` 测每关的有效窗口（OMG 加宽后中位 ±118 ms）。

## 下落/跳跃、钻石、皇冠
- 下落/跳跃后 0.35 s 内不能有点（MIN_AIR_GAP，validate.py）；引擎会缩短飞行让线在下一点前着地（d0f74b4）。
- 钻石不放在转角上（25c658c “diamonds off corners”）；OMG 有 10 颗钻石、2 个皇冠、3 次下落（refine 报告）。

## 路面表现（方案 C）
- 纸带路：奶油色路顶 + 金色台阶边 + 棕褐路体，unlit（78b8de5）；路面永远是最亮、最干净的元素（设计调研结论）。
- 纸模式下只画线头后 9 s 到前方 24 s 的路块（路体+路顶 24.6k → ~5k 三角形，b6a3826）；showfx 保留完整缓冲。
- 路面材质/路边不能被书页覆盖（8ff05f1 “pages never cover the road (+test)”）；台地、页堆边缘不能横穿任何路（5d46e34、2947b43）。

## 历史教训
- 早期路线（Ditto）用编排搜索做了折返、U 形弯、爬升螺旋、多层交叉（74296db），How Sweet 有 73 处立体交叉——这些都是“前进”规则之前的做法；重审其余歌曲时要按 FORWARD 规则检查。
- 改宽路后场景净空跟着变（近处物件按路边相对放置/网格推开），记得重新跑场景生成和 validate。
- 重新出谱或改路宽后要重跑 `node tools/build-levels.mjs`，且 refine 曾把路边裁切从 6% 改回 11%（31fd69a 修回）→ 合并后检查 layout 字段没被旧值覆盖。
